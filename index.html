Honest assessment

Where we're behind — and why it matters

Three gaps are worth naming directly. None of them require new tools. All of them require changing how we work together.

Highest drag

Problem definition is too slow

We named this ourselves. The irony: we have AI tools that can generate solutions fast — but if we arrive at the wrong problem, that speed works against us. The bottleneck is the start of the process, not the execution.

The report shows AI accelerates iteration once direction is set. The teams that move fastest have a shared, lightweight alignment ritual before anyone opens Figma or a prompt.

Highest drag

Prototypes aren't our default

43% of teams in the report expect functional prototypes as standard deliverables. We're still defaulting to mockups for work that would move faster — and get better feedback — as a functional prototype.

Some has Figma Make. Some can build in code. We have the capability. What's missing is a shared agreement on when to switch modes.

Medium drag

Individual knowledge isn't team knowledge

Denise built a UX heuristics critique skill, a senior dev workflow, and a competitor analysis generator. Juan has MCP pipelines that auto-synthesize Notion docs. Dani built a DS documentation agent, a design decision logger, and a Figma flow analyzer that detects edge cases automatically — and has deep research and documentation patterns. None of this is accessible to the rest of the team.

None of this is accessible to the others. The report describes exactly this situation in teams that are technically capable but not yet compounding — the knowledge is there, but it's siloed. On a 4-person team, shared knowledge is one of the highest-leverage investments we can make.

The honest bottom line

We're not behind on tools or individual capability. We're behind on turning individual capability into team practice. That's a much more fixable problem.

What we do next

Four concrete moves — in order of leverage

None of these require new tools, new headcount, or a long process. All of them require showing up differently.

1
Fix problem definition first
Introduce a shared 20-minute alignment ritual before any project enters design mode. A short AI-assisted frame: what problem, for whom, what does "done" look like, what's out of scope. The goal isn't documentation — it's shared clarity before anyone opens Figma or writes a prompt. This one change will make everything else faster.
2
Agree on a "prototype by default" trigger
Decide together: if it involves a user flow with more than two states, we prototype instead of mockup. We already have the tools (Figma Make for interactions, Claude Code for functional prototypes). What's missing is a team agreement. Proposal: try it on one project in the next two weeks and compare the feedback quality.
3
Two "show me your workflow" sessions — Denise and Dani
30 minutes each. Denise walks through the UX critique skill, senior dev mode, and competitor analysis generator. Dani walks through the DS documentation agent, the design decision logger, and the Figma flow analyzer that catches edge cases and error states automatically. These aren't trainings — they're demos. The goal is making these tools available to everyone, especially the flow analyzer, which is immediately useful across all design work.
4
Create one shared space for prompts and workflows
A single place — a Notion page, a shared Claude project, a Slack channel — where we drop what's working. Not a formal library. Just a living collection of prompts, shortcuts, and small discoveries. 10 minutes a week of contribution. The report shows peer knowledge-sharing doubled year-over-year as the primary way designers advance. We have four very different skill sets — that's a high-signal collection if it's visible to everyone.
